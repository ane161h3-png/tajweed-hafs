# تعلّم التجويد

برنامج تعليمي لأحكام تجويد القرآن الكريم ومخارج الحروف وصفاتها، برواية حفص عن عاصم من طريق الشاطبية.
الواجهة كلها بالعربية (من اليمين لليسار)، وتعمل على كل الأجهزة، ودون إنترنت للنصوص.

## الروابط
- **الموقع (كل الأجهزة):** https://ane161h3-png.github.io/tajweed-hafs/ ثم «ثبّت التطبيق» أو «إضافة إلى الشاشة الرئيسية».
- **أندرويد (APK):** https://github.com/ane161h3-png/tajweed-hafs/releases/latest/download/tajweed-hafs.apk

ينشرهما `.github/workflows/web.yml` و`.github/workflows/android.yml` تلقائياً بعد كل تحديث على الفرع `main`.

## المتطلبات

- Python 3.11 أو أحدث
- Node.js 20 أو أحدث

## التشغيل لأول مرة

```bash
# 1) بيئة بايثون ومكتباتها
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt

# 2) مكتبات الواجهة
cd frontend
npm install
cd ..

# 3) تنزيل البيانات العامة وتوليد ملفات source-data
.venv\Scripts\python scripts\fetch_sources.py --check-audio

# 4) بناء قاعدة البيانات
.venv\Scripts\python scripts\build_db.py

# 5) كتابة مسودة دروس الأحكام (مرة واحدة فقط)
.venv\Scripts\python scripts\seed_ahkam.py

# 6) محتوى المخارج والصفات، وبنك الأسئلة، والرسوم
.venv\Scripts\python scripts\seed_letters.py
.venv\Scripts\python scripts\build_quiz.py
.venv\Scripts\python scripts\make_makharij_svg.py
```

- `seed_letters.py` يكتب `data/content/letters.json`. صفات كل حرف تُحسب من مجموعات حروفها في الجزرية («فحثه شخص سكت» …)،
  وقوته من عدد صفاته القوية مطروحاً منها الضعيفة.
- `build_quiz.py` يولّد نحو ٣٠٠ سؤال في `data/content/quiz.json` من الحروف والدروس ومواضع الأحكام في المصحف.
  أعد تشغيله بعد تعديل الدروس.
- `make_makharij_svg.py` يولّد رسوم المخارج. انظر `frontend/src/assets/makharij/README.md` لاستبدالها برسوم مصمم.

## العمل دون إنترنت (PWA)

في نسخة الإنتاج (`npm run build` ثم الخادم على المنفذ 8000) يعمل البرنامج تطبيقاً قابلاً للتثبيت:
- عامل الخدمة `frontend/public/sw.js` يحفظ ملفات الواجهة، وكل ما فُتح من بيانات، ويعرضها عند انقطاع الاتصال.
- زر «حفظ النصوص للعمل دون إنترنت» في الإعدادات ← العرض والخط يحفظ المصحف كاملاً والأجزاء والدروس والمخارج والأسئلة مرة واحدة.
- التلاوات تُنزَّل سورةً سورة من «الاستماع»، وتُحفظ في IndexedDB.
- البحث النصي وتعديل الدروس يحتاجان الخادم.

- `fetch_sources.py` ينزّل الملفات الخام إلى `source-data/raw` ويولّد منها الملفات الستة، ويتحقق من روابط الصوت.
- `build_db.py` يطبع عدد السور والآيات والأحكام، وأي تنبيه في البيانات (عدد آيات لا يطابق، أو موقع حكم خارج النص).
- `seed_ahkam.py` لا يكتب فوق ملف الدروس إن كان موجوداً، حتى لا تضيع تعديلاتك.

### مصدر كل ملف في source-data

| الملف | المصدر |
|---|---|
| `quran-tajweed-hafs.json` | نص تنزيل العثماني (النسخة التي بُنيت عليها مواضع cpfair) مع مواضع الأحكام من cpfair/quran-tajweed |
| `surahs.json`، `juz-starts.json` | بيانات تنزيل الوصفية `quran-data.js` |
| `tajweed-rules.json` | الأحكام الـ18 وعدد مواضعها محسوباً من البيانات، والأسماء والألوان في `scripts/fetch_sources.py` |
| `reciters.json`، `minshawi-library.json` | everyayah.com (آية آية) وmp3quran.net (السورة كاملة) |

## دروس الأحكام: الورقة والتعديل

كل درس في قسم «أحكام التجويد» ورقة دفتر فيها: التعريف لغةً واصطلاحاً، والحروف، وطريقة الأداء،
والأمثلة من القرآن، وجدول اختياري، والاستثناءات، والفوائد والتنبيهات، والأبيات من التحفة والجزرية.

- **التعديل:** اضغط «✎ تعديل» أعلى الورقة، فتصير كل الخانات قابلة للكتابة على سطور الدفتر. احفظ بزر «حفظ» أو Ctrl+S.
- **إضافة مثال:** اختر السورة ورقم الآية، فتظهر الآية كلماتٍ قابلة للضغط. اضغط كلمة الشاهد لاختيارها،
  ومع Shift تختار عدة كلمات متتالية. تُحفظ الكلمة كما رُسمت في المصحف.
- **إضافة درس:** زر «+ درس جديد» في فهرس كل باب. **حذف درس:** «حذف الدرس» في وضع التعديل.
- **حالة المراجعة:** كل الدروس الآن «مسودة · يراجعها المقرئ». بعد مراجعة الشيخ للدرس اختر «رُوجع واعتُمد».
- **الحفظ:** في `data/content/ahkam.json`، وتُحفظ نسخة احتياطية تلقائياً قبل كل تعديل في
  `data/content/backups/` (آخر 50 نسخة). لنقل الدروس إلى جهاز آخر انسخ هذا الملف، أو نزّله من `/api/content/export`.
- **التحقق:** الاختبار `test_every_lesson_example_is_found_in_its_ayah` يتأكد أن كل كلمة شاهد موجودة فعلاً في آيتها.

> المحتوى العلمي الحالي مسودة كُتبت من المعروف في كتب التجويد لرواية حفص من طريق الشاطبية،
> والأبيات من تحفة الأطفال والمقدمة الجزرية. المواضع التي فيها خلاف بين أهل الأداء معلّمة بـ `TODO: يراجعها المقرئ`.
> يجب أن يراجعها مقرئ متخصص قبل اعتمادها للتدريس.

### البحث

شريط واحد يفهم:

- اسم السورة بأي إملاء: «البقره» و«البقرة» و«بقره» و«سورة البقرة».
- رقم السورة: `36`، أو سورة:آية: `2:255` و`٢:٢٥٥` و`2 255`.
- السورة والآية: «البقرة 255».
- الجزء: «جزء 30» و«الجزء الثلاثون» و«الجزء الحادي والعشرون» و«جزء عم».
- نص الآية بلا تشكيل: «الله لا اله الا هو». الكلمة الأخيرة تُطابَق كبادئة فتظهر النتائج أثناء الكتابة.

التطبيع: حذف التشكيل وعلامات الضبط والوقف، وتوحيد أ إ آ ٱ إلى ا، وى إلى ي، وة إلى ه.
يُفهرس نص كل آية بصيغتين: الألف الخنجرية محذوفة (ٱلرَّحْمَٰنِ ← الرحمن) ومكتوبة ألفاً (ٱلْكِتَٰبُ ← الكتاب)،
فيجد المستخدم الآية بالإملاء الحديث أو بإملاء الرسم.

## كيف أعدّل…

- **الأقسام وعناوينها:** `frontend/src/data/sections.js`، ومنه يُبنى الشريط الجانبي والسفلي ومسار التنقل والرئيسية.
- **ألوان الواجهة:** متغيرات `:root` و`.dark` في أعلى `frontend/src/index.css`.
- **ألوان الأحكام:** في `source-data/tajweed-rules.json`، ثم أعد بناء القاعدة. ويمكن للمستخدم تغييرها من الإعدادات (المرحلة السادسة).
- **إضافة قارئ:** سطر واحد في `source-data/reciters.json`. الخادم يقرأ الملف مباشرة، فلا حاجة لإعادة البناء.
- **الدروس:** من داخل البرنامج نفسه (زر «تعديل»)، أو بتحرير `data/content/ahkam.json` مباشرة.
- **إذا تغيّرت بنية ملف في المصدر:** عدّل دالة `load_*` الخاصة به فقط في `scripts/quran_data.py`.

## على كل الأجهزة: موقع يُثبَّت تطبيقاً (PWA)

نسخة واحدة تعمل على أندرويد وآيفون وآيباد وويندوز وماك ولينكس من المتصفح، وتُثبَّت على الشاشة الرئيسية كأي تطبيق،
وتعمل **دون خادم**، و**دون إنترنت** بعد حفظها مرة واحدة (زر «احفظ الآن» في الرئيسية، نحو ١١ م.ب).

```bash
.venv\Scripts\python scripts\export_static.py
cd frontend
npm run build:web
```

الناتج في `frontend/dist-web`: ملفات ثابتة تُرفع إلى أي استضافة:
- **Netlify Drop** (الأسهل): افتح https://app.netlify.com/drop واسحب إليه مجلد `dist-web` (أو `tajweed-web.zip`)، فتحصل على رابط فوراً.
- **GitHub Pages**: ارفع المشروع إلى مستودع، وفعّل Pages (Source: GitHub Actions)، فينشره `.github/workflows/web.yml` على
  `https://<المستخدم>.github.io/<المستودع>/` بعد كل تحديث.
- **Cloudflare Pages** أو أي استضافة ثابتة: ارفع محتوى `dist-web` كما هو. الملفان `_redirects` و`404.html` يجعلان الروابط العميقة تعمل.

إن كان الموقع في مجلد فرعي فاضبط المسار قبل البناء: `VITE_BASE=/اسم-المجلد/`.

التثبيت على الأجهزة:
- **أندرويد (Chrome)** وويندوز وماك (Chrome/Edge): زر «ثبّت التطبيق» في الرئيسية، أو من قائمة المتصفح.
- **آيفون وآيباد (Safari)**: زر المشاركة ← «إضافة إلى الشاشة الرئيسية».

## تطبيق أندرويد (Capacitor)

التطبيق يعمل بالكامل على الهاتف **دون خادم ولا إنترنت** للنصوص: المصحف والأحكام والدروس والمخارج والصفات والأسئلة
والبحث كلها داخل التطبيق. الإنترنت يلزم فقط لتشغيل التلاوات (ويمكن تنزيل السور للاستماع دونه).

كيف يعمل:
- `scripts/export_static.py` يصدّر ردود الخادم كلها ملفات JSON في `frontend/public/data` (نحو ١١ م.ب)، مع فهرس للبحث.
- عند البناء بـ `--mode android` (الملف `frontend/.env.android` فيه `VITE_STATIC=1`) يقرأ التطبيق من هذه الملفات بدل الخادم.
  البحث والمطابقة مكتوبان أيضاً بـ JavaScript (`src/lib/search.js`، `src/lib/arabic.js`)، والاختبار
  `tests/frontend/static.test.js` يتأكد أنهما يطابقان الخادم.
- تعديل الدروس في التطبيق يُحفظ على الهاتف نفسه.

### البناء

```bash
# 1) تصدير البيانات (بعد أي تعديل في الدروس أو المحتوى)
.venv\Scripts\python scripts\export_static.py

# 2) بناء الواجهة ونسخها إلى مشروع أندرويد
cd frontend
npm run build:android
```

ثم أحد طريقين لإخراج ملف APK:

- **على جهازك:** ثبّت [Android Studio](https://developer.android.com/studio) (يحتاج نحو ٥ ج.ب)، ثم `npm run android`
  يفتح المشروع، ومن القائمة Build ← Build APK(s).
- **على GitHub دون تثبيت شيء:** ارفع المشروع إلى مستودع على GitHub، فيبني `.github/workflows/android.yml` ملف APK تلقائياً.
  تجده في صفحة التشغيل تحت Artifacts باسم `tajweed-apk`.

الأيقونات وشاشة البداية مولّدة بـ `scripts/make_android_assets.py`. معرّف التطبيق `com.Hussein.tajweed` (الشيفرة تبقى في الحزمة app.tajweed.hafs)
في `frontend/capacitor.config.json`؛ غيّره قبل النشر على متجر Google Play، ولا تغيّره بعد النشر.

## التغليف لاحقاً

الواجهة تطبيق ويب عادي، والخادم مستقل عنها:

- **Tauri أو Electron:** غلّف `frontend/dist` وشغّل الخادم محلياً، أو صدّر البيانات JSON ثابتة.
  عيّن `VITE_API_BASE` على عنوان الخادم عند البناء.
- **Capacitor:** نفس الواجهة. أصول `tauri://` و`capacitor://` مسموحة في CORS مسبقاً.
